# Solar site assessment collaboration

These instructions apply to Ontario solar site assessment work in this project, not unrelated capstone documents.

Use the existing `solar-site-land-soil` skill and `skills/solar-site-land-soil/scripts/pipeline.py`. Read `docs/solar-multi-agent.md` when running or maintaining the multi-agent workflow. All generated role instructions, code comments, reports, maps and invocation examples are in English. Preserve original source data.

For a requested multi-agent assessment, the primary agent is the coordinator. Confirm the address, jurisdiction and public assessment parcel before delegating parcel-level analysis. Record boundary source, confirmation evidence, CRS and a SHA-256 fingerprint with `scripts/solar_agents.py init`. Complete Land Location and Size in the run's `coordinator/assessment.json`; retain PIN, ARN, recorded acreage and measured acreage separately. Do not derive ownership boundaries from geocoder extents.

Delegate the requested independent sections to `land_environment`, `grid_access` and `planning`, at most three specialists concurrently. Give each agent the absolute run directory, its assignment.json and confirmed manifest.json. Limited land/soil requests use only `land_environment`. If a custom role is unavailable in the current client, spawn a built-in worker with that role file's instructions explicitly included; do not silently run three sequential prompts and call it multi-agent execution. Do not create separate user-owned chats for these subtasks.

Workers read the shared boundary without changing it and write only inside their assigned directories. Workers do not delegate further. They return result.json using `schemas/agent-result.schema.json`, their exact assigned indicators, evidence files and a concise summary. Reuse existing pipeline operations for deterministic calculations. Maintain source dates and distinguish observations from interpretations. If tools require a shared browser tab, serialize access or allocate separate tabs; never operate another worker's tab concurrently.

After specialists complete, run `solar_agents.py validate`, then delegate independent evidence review to `evidence_reviewer`. Its output follows `schemas/agent-review.schema.json` and fingerprints the exact reviewed files, including coordinator/assessment.json. Unsupported conclusions must be revised or downgraded. A known, clearly reported skip is not a failure. Corrections require validation and review of the changed files again. Only the coordinator runs `solar_agents.py assemble`, then the existing pipeline's validate/report/gallery operations. Generate PDFs only when requested and use the PDF workflow.

Do not assign overall project Pass/Fail or development approval. Exclude GeoWarehouse; skip other login-dependent indicators individually. No credentials, utility contact, connection applications or paid services are authorized by this workflow. The skill's existing authorization for standard Hydro One public map-viewing terms remains applicable. Source outages, host permission failures and unavailable data are distinct. Stop after one timeout retry.

For setup validation, offline replays and tests use saved evidence and temporary run directories. A manifest with offline=true prohibits live source queries and browser retrieval; mark missing saved indicators skipped. These runs do not establish fresh grid capacity, current planning status or current source availability. Instructions about output ownership do not create separate OS sandboxes; all agents inherit the parent session's actual permissions.
